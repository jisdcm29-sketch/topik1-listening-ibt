# TOPIK I 듣기 — 음성 중단 자동 진단 (검증 단계)

## 현재 구현
- `audio-diagnostics.js` 모듈만 추가, `index.html`에 읽기 전용 진단 스크립트 연결
- `waiting`, `stalled`, `error` 이벤트 및 재생 위치 정체 감시
- 버퍼링 6초 또는 음원 위치 8초 정체 시, 중복 제한하여 브라우저에 저장 (최대 60건)
- 저장 항목: 시각, 세션 식별자, 시험 이름, 문항 표시 번호, 오디오 파일 상대경로, 재생 위치/길이, 네트워크·미디어 상태, 브라우저 종류
- 학생 이름·전화번호·정답·비밀번호는 진단 데이터에 넣지 않음
- 이상 발견 시 '음성 오류 기록 저장' 버튼으로 JSON 파일 다운로드
- 오디오 재생·일시정지·위치 변경·문항 이동·제출·채점 코드와 Google Sheets 성적 기록은 변경하지 않음

## 원격 자동 보고 — 미연결
현재 운영 Google Apps Script는 `log_result` 성적 기록용으로만 확인되며 `log_audio_issue` 수신을 지원한다는 증거가 없다. 이 URL로 오류를 보내면 안 된다.

전용 오류 수신 Apps Script 웹앱을 만들고 `log_audio_issue` 처리를 확인한 다음에만, `audio-diagnostics.js`보다 앞에 아래 코드를 배치할 것:

```html
<script>window.TOPIK_AUDIO_DIAGNOSTICS_ENDPOINT = "https://script.google.com/macros/s/VERIFIED_RECEIVER_ID/exec";</script>
```

현재 브랜치에는 전용 수신 URL을 지정하지 않았으므로 **오류 기록은 브라우저에 자동 저장되지만 서버로 자동 전송되지는 않는다**.

## 검증 체크리스트
1. 실전 A~G, 문항 선택, 레벨테스트, 랜덤 시험에서 기존 재생/선택지 동작 동일
2. 개발자 도구 Network를 Offline으로 변경: 지연/에러 기록 생성, 답안 및 진행 위치 유지
3. 정상 긴 음원 25~30번에 허위 오류가 남지 않는지 검증
4. 음성 정상 종료 `ended` 뒤 추가 문항 이동이 없는지 확인
5. 브라우저 새로고침 뒤 최근 기록이 보존되는지 확인
6. 오류 보고 JSON에 개인정보가 포함되지 않는지 검사
7. 기존 Google Sheets 성적 수집이 영향을 받지 않는지 확인

## 배포
이 변경은 검증 브랜치에만 있다. 운영 `main`에는 적용되지 않았다.
운영 배포 전에 테스트 환경에서 7개 회차와 Chrome/Edge, 느린 네트워크 재현 검증이 필요하다.
